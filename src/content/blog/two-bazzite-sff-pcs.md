## The role comes before the parts

Small-form-factor PCs often begin as a packaging challenge: fit the fastest hardware into the smallest case. I was more interested in giving two compact systems distinct jobs.

The higher-end machine combines a Ryzen 5 5600, Radeon RX 9070 XT, 32 GB of memory, and a 1 TB SSD. The second uses a Ryzen 5 3600, Radeon RX 9060 XT 16 GB, 16 GB of memory, and a 1 TB SSD. Both run Bazzite.

The component lists are different, but the important common choice is the operating system. Bazzite turns them from generic desktops into focused, controller-friendly Linux machines.

## Why Bazzite

A conventional desktop distribution can launch games perfectly well. It also exposes an endless set of choices before reaching the thing the computer is for. Bazzite provides an opinionated gaming surface while keeping a real Linux system underneath.

That balance matters. From the couch, the machine can behave like a console. When something needs to be configured, it remains inspectable. I do not have to choose between convenience and ownership.

## The RX 9070 XT system

The Ryzen 5 5600 build is the more ambitious of the pair. Its GPU gives it enough headroom for high-resolution play while the compact enclosure keeps the machine easy to place near a display.

It is not intended to replace Creekwood, my primary RTX 5080 desktop. The larger desktop remains the workstation and maximum-performance machine. The small Radeon system has a narrower purpose: make high-end PC gaming feel immediate in a different room and interface.

## The RX 9060 XT system

The Ryzen 5 3600 machine occupies the secondary role. Its 16 GB GPU configuration provides room for modern workloads without turning the build into a duplicate of the faster system.

That distinction is important. A secondary computer becomes useful when it has a reason to exist, not when it is merely the older version of another computer. This one is a place for Linux gaming, testing, and a different display setup without disturbing the primary system.

## AMD hardware and a Linux-first surface

The all-Radeon approach keeps the machines aligned with the Linux-first goal. Driver integration is not the only factor in a build, but reducing friction between the graphics stack and the operating system helps preserve the console-like experience.

The small cases add their own constraints:

- airflow has to be deliberate;
- cable routing affects serviceability;
- noise matters when the system sits near a television;
- component dimensions matter as much as benchmark charts.

Those constraints are part of the appeal. The build becomes a complete object rather than a list of independently optimal parts.

## Console-like does not mean locked down

The best part of this setup is not pretending a PC is a console. It is borrowing the console’s focus while keeping the PC’s openness. I can start with a controller, reach a game quickly, and still drop into the underlying system when I want to understand or change something.

> A focused interface can make a general-purpose computer feel more capable, not less.

## What the two-machine experiment taught me

Hardware becomes easier to evaluate when every machine has a stated role. Creekwood is the main desktop. The RX 9070 XT SFF machine is the high-end compact gaming system. The RX 9060 XT machine is the secondary Linux box.

That clarity prevents the collection from becoming repetition. It also makes future changes easier: upgrade the role that has a real constraint, not the machine with the most tempting parts list.
